# 费用报销系统电子单据自动打印 - 设计规格

> 版本：v1.0（已确认）
> 日期：2026-04-30
> 状态：✅ 所有需求已确认

## 1. 概述

### 1.1 背景与目标
费用报销流程中，员工需打印电子发票（PDF）用于报销审核。传统模式依赖人工操作，容易出现遗漏、延迟等问题。

**核心目标**：
1. 电子发票（PDF）自动打印
2. 支持定时批量打印 + 手动补打
3. 异常检测与通知（邮件/Teams）
4. 后台状态管理与统计

### 1.2 一期范围
| 维度 | 范围 |
|------|------|
| 业务范围 | 个人费用报销 |
| 适用站点 | 北京站点 |
| 文档类型 | 电子发票（PDF） |
| 用户规模 | 1人（试点） |

## 2. 系统架构

### 2.1 整体架构

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│   报销系统 API  │────▶│   票据拉取器    │────▶│   打印调度器    │
│  （电子票据）   │     │  （定时拉取）   │     │  （定时+手动）  │
└─────────────────┘     └─────────────────┘     └─────────────────┘
                                                        │
                                                        ▼
                                                ┌─────────────────┐
                                                │   打印执行器    │
                                                │（Print Server） │
                                                └─────────────────┘
                              ▲                       │
                              │                       ▼
                        ┌─────────────────┐     ┌─────────────────┐
                        │   状态存储      │◀────│   通知服务      │
                        │  （SQLite）     │     │ （邮件/Teams）  │
                        └─────────────────┘     └─────────────────┘
```

### 2.2 核心组件

| 组件 | 职责 | 技术选型 |
|------|------|----------|
| 打印调度器 | 定时扫描、手动触发、任务队列 | Node.js + node-cron |
| 文件监听器 | 监控指定文件夹的新 PDF 文件 | Node.js + chokidar |
| 打印执行器 | 调用系统打印 API | PowerShell (Windows) |
| 状态存储 | 记录打印任务状态 | SQLite |
| 通知服务 | 异常告警 | QQ邮箱 SMTP / Teams Webhook |
| Web 管理后台 | 查看状态、手动操作 | 轻量级 Node.js HTTP 服务 |

### 2.3 数据流

```
1. [新文件检测] → 文件进入待处理队列
2. [定时触发] → 扫描待处理队列
3. [打印执行] → 调用系统打印
4. [状态更新] → 记录成功/失败
5. [异常通知] → 失败时发送通知
```

## 3. 功能模块

### 3.1 票据拉取模块
- 对接报销系统 API，定时拉取电子票据
- 拉取频率：每日 8:00、12:00、18:00（共3次）
- 文件格式：PDF（直接从 API 获取或下载链接）
- 重复检测：基于票据 ID 去重（避免重复打印）
- 拉取后本地缓存：`./cache/` 目录

### 3.2 打印调度模块
- **定时打印**：每日 18:00 自动执行
- **手动打印**：支持指定文件即时打印
- **批量打印**：支持全量重打

### 3.3 打印执行模块（方案 B：中央打印服务）
- 架构：客户端 → Windows Print Server → 网络打印机
- 调用 Print Server 队列 API
- 支持指定打印机队列名称
- 超时设置：单文件 60s（含网络延迟）
- 重试机制：失败自动重试 3 次
- 打印任务状态同步（通过 Print Server API）

### 3.4 状态管理模块
- 任务状态：`pending` | `printing` | `success` | `failed`
- 记录字段：文件名、路径、状态、时间戳、错误信息
- 持久化：SQLite 数据库

### 3.5 通知模块
- 通知触发条件：打印失败
- 通知渠道：QQ邮箱 + Teams（双重通知）
- QQ邮箱：nodemailer + SMTP
- Teams：Adaptive Card Webhook
- 通知内容：票据信息、错误原因、重试建议、操作链接

### 3.6 Web 管理后台（完整版）
- 路径：`http://localhost:3000`
- 功能列表：
  - **Dashboard**：今日统计（总数、成功、失败）、本周趋势图
  - **任务列表**：筛选（状态/日期）、分页、搜索
  - **手动操作**：重试、取消、重新打印、批量重试
  - **设置**：API 配置、打印服务器配置、通知渠道配置
  - **日志查看**：操作日志、错误日志

## 4. 数据模型

### 4.1 PrintTask 表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER | 主键，自增 |
| fileName | TEXT | 文件名 |
| filePath | TEXT | 文件完整路径 |
| fileHash | TEXT | MD5 哈希（去重用） |
| status | TEXT | pending/printing/success/failed |
| createdAt | DATETIME | 创建时间 |
| printedAt | DATETIME | 打印时间（成功时） |
| errorMsg | TEXT | 错误信息（失败时） |
| retryCount | INTEGER | 重试次数 |

## 8. 部署架构

### 8.1 一期部署（单用户）
- **打印客户端**：北京站点员工 PC，Node.js 应用
- **打印服务器**：Windows Print Server（共享打印机）
